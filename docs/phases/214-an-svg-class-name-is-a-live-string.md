# Phase 214 — an SVG class name is a live string

## 1. What was wrong

`Element.className` reflected `class` as a JavaScript string for every
namespace. SVG instead exposes `SVGElement.className` as an
`SVGAnimatedString`: code such as `circle.className.baseVal` received
`undefined`, and writing that property did not update the element. This was
one of the unimplemented SVG DOM questions in
`tests/dom-conformance/open/dates-and-svg.js`.

## 2. What changed

`SVGElement.prototype.className` is a read-only accessor returning a cached,
realm-owned `SVGAnimatedString`. Its `baseVal` reads and writes the element's
`class` attribute using DOMString conversion; `animVal` is a read-only live
view of the same value when no animation is applied. Attribute and `classList`
changes are reflected immediately. Different elements have distinct views,
while repeated reads on one element return the same object. Retaining the view
keeps its detached element and script wrapper alive through GC. The interface
is exposed but cannot be constructed by script; its accessors check the
receiver. HTML's string-valued `className` is unchanged.

## 3. Evidence

`tools/conformance/verify_svg_class_name.py` runs the same 20 labeled probes in
Chromium and Litebird: **1/20 before, 20/20 after**. It covers identity,
branding, live attribute/classList changes, writing `baseVal`, selector
matching, conversion, read-only properties, illegal receivers and HTML
controls. The suite `svg_class_name_is_a_live_animated_string` adds an explicit
detached-node GC check. The browser's expected output is not recorded from
Litebird; the script obtains it from a live headless Chromium on each run.

From a clean workspace, with Node.js and npm:

```sh
make -j2 build/litebird
npm install --prefix build/svg-oracle @sparticuz/chromium@131.0.1 puppeteer-core@23.11.1
mkdir -p build/svg-oracle/runtime
node -e "require('fs').createReadStream(process.argv[1]).pipe(require('zlib').createBrotliDecompress()).pipe(process.stdout)" \
  build/svg-oracle/node_modules/@sparticuz/chromium/bin/al2023.tar.br | tar x -C build/svg-oracle/runtime
python3 tools/conformance/verify_svg_class_name.py    # 20/20
make test
```

The Chromium package uses Linux shared libraries; minimal systems may also
need NSS libraries in `LD_LIBRARY_PATH`. The verifier sets the package's
runtime path and preserves any existing `LD_LIBRARY_PATH`. For a before/after
comparison, build an old binary and pass `--binary path/to/binary`; the
expectation is still generated by Chromium, not the new implementation.

## 4. What is still open

SVG animation is not implemented for this attribute: `animVal` equals
`baseVal`, and this is not a claim of SMIL or CSS animation support. Other
`SVGAnimatedString` attributes are not wired to this interface, and `viewBox`,
`getBBox()`, SVG geometry and the broader SVG DOM remain separate work. The
20 comparisons do not measure visual SVG rendering or full WebIDL compliance.
