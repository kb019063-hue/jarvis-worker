## Phase 192 — `Array.prototype.toLocaleString` asks the element, and `Object`'s asks `toString`

Phase 177 fixed this for `%TypedArray%.prototype.toLocaleString` and named the rest: `Number.prototype.toLocaleString = () => "X"` left `[1,2].toLocaleString()` as `1,2`, and `[1,,3]` as `1,,3`. The fix existed then and was withdrawn — it needed `src/js/BuiltinsArray.cpp` and `src/js/JsOps.cpp`, and #176 held both. `AGENTS.md` kept the row with the numbers it had measured.

`Array.prototype.toLocaleString` was `join_array(receiver, ",")`: the same walk `join` takes, reading each place and formatting it. §23.1.3.28 is not `join`. It takes `Len(Get(O, "length"))` once, and for each place reads the element (`Get`, so a hole the prototype fills is an element and a getter on one runs once), writes a `,` before every place after the first, and for an element that is neither `undefined` nor `null` does `Invoke(nextElement, "toLocaleString")` and `ToString` of the answer. A hole and `undefined` are the empty string with nothing asked, which is what makes `[1,,3]` be `"X,,X"` under a patched `Number.prototype`.

The element is passed as it was read. §23.1.3.28 step 7.c has no ToObject in it, so a strict method sees the number it was given and a sloppy one is boxed by the call — `typeof this` is `"number"` under `"use strict"` and `"object"` without, exactly as `(function () { return typeof this; }).call(42)` is. test262's `primitive_this_value` and `primitive_this_value_getter` ask this, and the first version here boxed the element before the call, which they refused.

That left both of those cases failing for a second reason, in a file the row did not name: `Object.prototype.toLocaleString` was `js_to_string(self())`, which for every object is `"[object Object]"` and asks nothing. §20.1.3.5 is `Invoke(this, "toString")` — the method is looked up on the receiver and called. The test sets `Boolean.prototype.toString = function () { return typeof this; }` and reaches it through the element's inherited `toLocaleString`; without the lookup the answer was `"true,false"` where the test wanted `"boolean,boolean"`. It is now the invocation, `src/js/BuiltinsObject.cpp` included in a phase whose row named neither.

**What is still open.** `Array.prototype.toLocaleString` takes no `locales` or `options` and passes none to the element, so `[1].toLocaleString("de")` is not the browser's answer: no call in the engine to a `toLocaleString` carries an argument (`src/js/BuiltinsNumber.cpp`, `src/js/BuiltinsDate.cpp`), and giving the method its two parameters is its own task. Typed arrays keep their separate §23.2.3.29 walker with the same shape but the receiver check Array's does not have, and the two do not share a walker. `%TypedArray%`'s method still passes no `locales` either. Nothing here touches the three `BigInt` cases.
