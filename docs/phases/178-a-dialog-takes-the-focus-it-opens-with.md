## Phase 178 — A dialog takes the focus it opens with, and gives it back

Phase 147 gave a closed dialog no box. It left the focus alone, and named that as the next thing: `showModal()` "still lacks top-layer rendering, backdrop, outside-input isolation and focus management".

The dialog element's [focusing steps](https://html.spec.whatwg.org/multipage/interactive-elements.html#dialog-focusing-steps) are now run by both `show()` and `showModal()`: a descendant with `autofocus`, else the first focusable descendant in tree order, else the dialog itself, which is given `tabindex="-1"` so that it can hold the focus and `Tab` can still leave it. `showModal()` records the document's focused element before it moves the focus, and `close()` gives the focus back to it; that is what makes the record worth keeping, and why an ordinary `show()` keeps none — there is nothing to give back, so `close()` unfocuses instead, which is the spec's other branch.

The two pieces of state are on the element, not in a script slot: `is_modal_dialog()` is the flag `showModal()` sets and `close()` clears, and `dialog_previously_focused()` is the element held until then. They are the state a top-layer painter and a modal hit test will read; today the dialog's own `close()` is the only reader. A previous focus that has left the document is dropped rather than restored, and the dialog then unfocuses.

`show()` on a dialog that is already open now throws `InvalidStateError` when the dialog is ordinary, which the spec asks for and which was silently a no-op; on a modal one it returns without touching the focus, because re-running the focusing steps there would take the focus out of a dialog the user is in.

`make -j2 build/litebird && tools/real_pages/dialog-02/check.sh`: **32/32 dialog focus checks passed**. Every click in it is a real one through the shell's hit path, so the focus that `showModal()` records is the one a mousedown put on the opener. The checks cover the first control, an `autofocus` descendant out of tree order, a dialog with no control at all, the restore after each, an ordinary `show()`/`close()` pair that restores nothing, `show()` on each kind of open dialog, and a previously focused element removed from the document before the close.

**What is still open.** The top layer is not painted: a modal dialog is laid out and painted where it sits in the document, so nothing is drawn over the page and no `::backdrop` exists. Nothing outside a modal dialog is inert: a real click on a button behind it reaches that button, and Tab still walks the whole document. `Escape` is not delivered by the shell, so the `cancel` event a modal dialog should get from it cannot be tested here. The `form method="dialog"` submit path, which closes a dialog with a `returnValue`, was already missing and is still missing.
